# Дизайн: срок жизни и отзыв API-токенов

Дата: 2026-10-05
Статус: утверждён пользователем

## Проблема

API-токены (`skh_`) сейчас бессрочные и их нельзя отозвать:

- Колонка `expires_at` в таблице `api_tokens` существует, но никогда не заполняется; фильтр по ней уже есть в `ApiTokenService.authenticate`.
- Нет DELETE-эндпоинта, нет колонки для ревока, нет кнопки в UI.
- API не возвращает `id` токена фронтенду — ревок не к чему привязать.

## Решение

### Бэкенд

**Миграция Flyway** (следующий номер, `skillhub-api/src/main/resources/db/migration/`):

```sql
ALTER TABLE api_tokens ADD COLUMN revoked_at TIMESTAMPTZ NULL;
```

**Домен и сервис (`ApiToken` domain model, `JpaApiToken`, `ApiTokenService`):**

- `createToken(User user, String name, Integer days)` — если `days != null`, `expiresAt = now() + days`; иначе `null` (бессрочно).
- `revokeToken(User user, UUID tokenId)` — ищет токен по id **и userId** (нельзя отозвать чужой токен), ставит `revokedAt = now()`; повторный вызов идемпотентен (не перезаписывает дату).
- `authenticate(rawToken)` — к существующей проверке `expiresAt` добавляется проверка `revokedAt == null`.

**REST (`TokenController`):**

- `POST /api/tokens` — тело `{ "name": "...", "lifetimeDays": 7 | 30 | 90 | null }` (null = бессрочно). Ответ 201 как раньше.
- `DELETE /api/tokens/{id}` — 204 при успехе; 404 если токен не существует или принадлежит другому пользователю.
- `GET /api/tokens` — в ответе каждого элемента добавляются `id`, `expiresAt`, `revokedAt`.

### Фронтенд (`ui/src/pages/TokensPage.tsx`)

- Форма создания: селект «Срок жизни» — варианты 7 дней / 30 дней / 90 дней / Бессрочно. По умолчанию «Бессрочно».
- Таблица токенов: колонки Имя / Создан / Истекает / Последнее использование / Действия.
  - «Истекает»: дата или «—» для бессрочных; просроченные — приглушённым цветом.
  - «Действия»: кнопка «Отозвать» с confirm-диалогом; для отозванных — текст «Отозван <дата>», кнопка скрыта.
- В модалке с сырым токеном отображается срок действия.

### CLI

Без изменений. Отозванный/истёкший токен перестаёт проходить авторизацию; существующая обработка 401 в CLI покрывает этот случай.

## Отклонённые альтернативы

- **Жёсткое удаление токена** — выбран мягкий ревок (сохраняется история «когда отозван»).
- **Кастомная дата истечения (датапикер)** — YAGNI, достаточно пресетов.
- **Проверка истечения без миграции** — ревок всё равно требует миграции; обе вещи делаются одним заходом.

## Тесты

- Юнит: создание токена с каждым из сроков (7/30/90) и бессрочно; ревок идемпотентен; ревок чужого токена → 404; `authenticate` отклоняет отозванный и истёкший токен.
- Миграция: применяется к текущей схеме без ошибок.

## Вне области

- Редактирование срока жизни существующего токена.
- Массовый ревок, ревок по имени.
- Уникальность имён токенов.
