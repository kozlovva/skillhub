# Дизайн: удаление элементов и версий (мягкое)

Дата: 2026-10-05
Статус: утверждён пользователем

## Проблема

Элементы и их версии нельзя удалить: ни REST-эндпоинтов, ни методов в use-case слое, ни кнопок в UI. Ошибочно опубликованный элемент или версию нечем убрать.

## Решение

Мягкое удаление: строки остаются в БД (обратимость, сохранность избранного/отзывов/рейтингов), скрываются из всех выборок. Объекты S3 не удаляются.

### Миграция Flyway (следующий номер, `src/main/resources/db/migration/`)

```sql
ALTER TABLE elements ADD COLUMN deleted_at TIMESTAMPTZ NULL;
ALTER TABLE element_versions ADD COLUMN deleted_at TIMESTAMPTZ NULL;
```

### Домен и права

- `Element` и `ElementVersion` — поле `Instant deletedAt`; в `JpaElement`/`JpaElementVersion` — колонка `deleted_at`; в мапперах прокидывается.
- `AccessService.canDelete(Element, User)`:
  - админ — всегда;
  - элемент команды — только OWNER (MAINTAINER нельзя);
  - личный элемент (`team == null`) — только автор.

### Use cases

**`ElementUseCase.delete(slug, user)`**:
- элемент не найден или уже удалён → 404;
- нет права → 403;
- элемент входит в состав любого пака (новый метод `PackContentRepositoryPort.findAllByElementId(UUID)`) → 409 со списком slug'ов паков;
- иначе `deletedAt = now()`, аудит `DELETE_ELEMENT`. Избранное/отзывы/рейтинги остаются в БД.

**`VersionUseCase.deleteVersion(slug, version, user)`**:
- элемент/версия не найдены или уже удалены → 404;
- нет права (право считается от элемента) → 403;
- какой-то пак закрепляет точную эту версию (`versionConstraint` равен строке версии; ограничение `latest` не блокирует) → 409;
- иначе `deletedAt = now()`. Если удалённая версия была `element.latestVersion` — пересчёт на последнюю не удалённую published-версию (при отсутствии — `latestVersion = null`, `latestChangelog = ""`), `updatedAt = now()`. Аудит `DELETE_VERSION`.

### Скрытие удалённого

- `ElementUseCase.getBySlug` / `listVisible` — удалённые элементы → 404 / исключаются (для всех, включая админа);
- `SearchAdapter.BASE_WHERE` — добавить `AND e.deleted_at IS NULL`;
- `VersionUseCase`: `listVersions` исключает удалённые версии, `getVersion` и `findLatestPublished` их не возвращают (404);
- CLI и скачивание ломаются естественно через 404.

### REST

- `DELETE /api/elements/{slug}` → 204; 403/404/409 по правилам выше.
- `DELETE /api/elements/{slug}/versions/{version}` → 204; аналогично.

### Фронтенд (`ui/src/pages/ElementPage.tsx`)

- Кнопка удаления элемента в шапке и действие удаления в строке `VersionTable` — видны только при праве удаления (для личных элементов нужен `authorId` в DTO элемента — добавить в ответ `ElementController`).
- Подтверждение — простой MUI Dialog: «Удалить <имя/slug@version>? Действие обратимо только администратором» с кнопками «Отмена» / «Удалить».
- После удаления элемента — редирект в каталог; после удаления версии — инвалидация `['versions', slug]` и `['element', slug]`, снекбар об успехе, ошибка — через `toApiError`.

### Тесты

- Юнит use cases: права (админ/OWNER/MAINTAINER/автор/чужой), блокировка по пакам, блокировка по точному constraint, `latest` не блокирует, пересчёт latest при удалении последней версии, повторное удаление → 404.
- Контроллеры: 204 / 403 / 404 / 409.
- UI: видимость кнопок по ролям, подтверждение отменяет удаление, подтверждение вызывает API и показывает снекбар.
- Миграция применяется к текущей схеме.

## Отклонённые альтернативы

- Жёсткое удаление с каскадом — выбрана мягкая модель (обратимость, проще S3).
- Ввод slug для подтверждения — пользователь выбрал простое подтверждение.
- Показ удалённых версий в таблице с пометкой — YAGNI.

## Вне области

- Восстановление удалённых элементов/версий из UI (данные позволяют сделать позже).
- Удаление команд, категорий, пользователей.
