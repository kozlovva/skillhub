# Поиск команд и видимость списка по ролям — Design Document

Дата: 2026-10-04
Статус: Approved

## 1. Обзор

Страница «Команды» не имеет поиска, а не-админ видит все команды, хотя состав чужих ему недоступен. Добавляем клиентский поиск по списку и ограничиваем видимость: не-админ видит в списке только свои команды (любая роль); нет своих — пустое состояние. Одновременно страница декомпозируется: логика TeamsPage разрослась (~345 строк), выделяем две панели в компоненты.

**Ключевые решения:**

| Решение | Выбор |
|---|---|
| Видимость списка для не-админа | Только свои команды (MEMBER/MAINTAINER/OWNER по JWT); нет своих — «Вы не состоите ни в одной команде» |
| Поиск | Клиентский, по `name` и `slug` (lowercase includes), мгновенный без debounce |
| Пустой результат поиска | «Ничего не найдено» |
| Декомпозиция | `TeamListPanel` (левая панель) + `TeamMembersPanel` (правая карточка); `TeamsPage` — оркестратор |
| Бэкенд | Без изменений (список команд не секретен; состав защищён 403) |

## 2. Компоненты

### 2.1. `ui/src/components/TeamListPanel.tsx`

Props:

```ts
interface TeamListPanelProps {
  teams: TeamResponse[];
  selected: string | null;
  onSelect: (slug: string) => void;
  isAdmin: boolean;
  authenticated: boolean;
}
```

Внутри: форма создания команды (только админ, своя мутация + snackbar + invalidate `['teams']`), TextField поиска (иконка `SearchIcon`, `size="small"`), фильтр по `name`/`slug` (lowercase includes), `ListItemButton`-список (стили как сейчас: avatar-инициал, name, slug).

Пустые состояния (в левой панели):
- `teams.length === 0` → «Команд пока нет» (админ) / «Вы не состоите ни в одной команде» (не-админ)
- фильтр дал пусто → «Ничего не найдено»

### 2.2. `ui/src/components/TeamMembersPanel.tsx`

Props:

```ts
interface TeamMembersPanelProps {
  team: TeamResponse;
  isMember: boolean;
  canManage: boolean;
  ownRoleLabel: string | null;
}
```

Вся логика правой карточки переносится как есть: запрос состава (`['team-members', slug]`, enabled по `isMember`), заглушка не-участника, список с Chip ролей, меню действий, confirm-диалог, блок добавления (Autocomplete), мутации (changeRole/removeMember/addMember + invalidate). Компонент не знает про админство напрямую — права приходят через `isMember`/`canManage`.

### 2.3. `TeamsPage.tsx` — оркестратор

- teams-запрос, `selected` + автовыбор первой видимой команды, фильтрация видимости, состояние поиска — поисковый state живёт внутри `TeamListPanel` (странице не нужен)
- Передача пропсов в обе панели; никаких запросов состава на уровне страницы
- ~80–100 строк

## 3. Правила видимости и поиска

- Не-админ: `teams.filter(t => myTeamRoles[t.slug])`; пусто → «Вы не состоите ни в одной команде» в левой панели, правая — «Выберите команду» (недостижимо, т.к. выбирать нечего)
- Поиск: регистронезависимый `includes` по `name` и `slug`; выбранная команда вне фильтра не сбрасывается (деталь не мигает)
- Админ ищет по всем командам

## 4. Тесты

- Существующие 3 теста `TeamsPage.test.tsx` адаптируются (useAuth-мок уже содержит `myTeamRoles`)
- Новые тесты TeamsPage:
  - фильтр по названию и slug; «Ничего не найдено» при пустом результате
  - не-админ (`myTeamRoles = { platform: 'OWNER' }`) видит только `platform`, не видит `other` в списке
  - не-админ без команд: «Вы не состоите ни в одной команде»

## 5. Не делаем

- Бэкенд-поиск/фильтрацию команд (список мал, фильтр клиентский)
- Пагинацию и сортировку списка
- Изменения бэкенда вообще (задача чисто фронтендовая)
